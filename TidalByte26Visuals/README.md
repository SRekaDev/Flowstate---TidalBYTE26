# Flowstate for Windows

## Setup
Install 64-bit Python 3.11 with its py launcher. Extract the entire ZIP and double-click Start-Flowstate.cmd (the original Start-TidalByte.cmd also works). The command window displays setup progress and any startup error. Leave it open while using the app. On first launch it installs dependencies in a local virtual environment. Enable camera access for desktop apps in Windows settings.

## Use
Click Start session. The webcam opens with a face-centering guide. Type naturally for 30 seconds of active practice. Then hold left, right, up, down and center for one valid second each. Timing pauses when tracking is lost, a detected hand covers the face, or the requested pose is missing. After setup the preview closes and the launcher minimizes. Open webcam in the launcher to see an unguided preview. Work in your own apps. Restore Flowstate and click Finish session to open your interactive report inside Flowstate. Closing the active window also finishes the session. Keep the computer awake during collection. Capture runs as a normal desktop process in the signed-in session. Windows reports are in %LOCALAPPDATA%\TidalByte\Reports. Open example report previews simulated data before capture.

The webcam and keyboard listener run locally after Start. The listener counts text and correction presses on the signed-in desktop in 30-second bins. It discards key identities and does not record text, application names or video. Camera loss yields missing observations. New sessions use the bundled Focus Engine face model and one-second rolling scores, summarized in 30-second windows. The existing head-turn limits identify forward-facing samples for a passive reference at the start of studying (about 20 seconds). Focus uses eye openness and head angle. Fatigue uses the fraction of frames with closed eyes, possible yawns and blink duration. Estimated stress combines brow movement, lip pressure and blink rate. Where the original engine expected a separate frown calibration, Flowstate uses its neutral-brow baseline mode. The engine uses its default reference of 15 blinks per minute. Keyboard counts remain separate activity measurements.

Scores are experimental behavioral estimates. Gaps indicate insufficient observations. A stress flag marks a window with a mean of at least 70/100 across at least 15 measured seconds. Older reports retain their original scores and definitions. Calendar views include older sessions. The usual-focus comparison uses sessions scored with the same method.

The report opens immediately in Flowstate. If there is enough tracker data, the penguin starts a local Nemotron review automatically. To opt out, clear the Nemotron checkbox before starting a session or opening the example. Keep the report window open while the penguin works. Use **Refresh Nemotron review** to check progress, then select **Show Nemotron review** when it’s ready. The finished review is saved in that same report and is available under **Review last session**. Tracking and the standard report work independently.

The review uses OpenClaw in the `tidalbyte26-retry` NemoClaw sandbox on gateway port `8990`, with Ubuntu 24.04 in WSL and `nemotron-3-nano:4b` running through local Ollama. Set the sandbox route to `ollama-local`, keep Ollama on loopback with cloud features disabled, and set OpenClaw's `tools.deny` to `["*"]` without explicit tool allowances. The app checks the route and tool restriction before sending aggregate data. The review needs no API key and does not send camera images or typed text.

## Interactive review and capture check
The penguin can point out when a focus dip coincides with more time facing away from the usual forward position. It can also mention longer eye closures or yawn-like movements observed near a fatigue peak. These are webcam observations and do not establish what you were looking at or what caused a change.

Use **Browse past sessions** to open an earlier report inside Flowstate. If that session has a saved Nemotron review, it appears below the summary without running the model again. Reports saved without a review still open.

Finish opens a dedicated Flowstate report window using Microsoft Edge WebView2. Close that window to return to the launcher. If the viewer cannot start, Flowstate shows its built-in basic review. Open Sample-report.html to preview the design without launching capture. Expand Camera and keyboard counts for capture diagnostics. Move over the plot or click it and use the arrow keys to inspect windows. Switch to Focus & fatigue for scores. Capture quality & score definitions explains missing measurements. Review last session reopens the latest new-format report. Older HTML reports remain in the Reports folder.

For a hardware check, run a three-minute session in good light with the webcam unobstructed. Type a short line in another app, then pause and face the screen. Finish and check that frames, usable samples and key presses were counted. Check the Session scores graph for focus, fatigue and estimated stress. Seeing counts verifies capture separately from score availability.

## Training with volunteers
1. Collect consented sessions that include reading, typing and quiet thinking. After each session, export window data from the real report. Each row represents up to 30 seconds. There are no images or typed words in the export.
2. After the session, have volunteers identify intervals they remember and rate focus, fatigue and stress separately from 1 to 5. Fill the corresponding rating columns for those intervals only. Leave uncertain ratings empty. Give each volunteer a pseudonymous participant_id and each session a unique session_id.
3. Combine the CSVs. Train a separate scikit-learn model per rating, using measurements such as corrections per key, camera coverage, orientation and eye-closure fraction. Fit transformations on training participants alone. Split by participant so all sessions from one person remain together. Never use IDs, rule-generated scores or synthetic example data as training targets.
4. Compare held-out mean absolute error to predicting the training-set median for each rating. Report coverage and per-person results. Integrate a learned model only once evaluation supports it. The shipped scores currently use rules.
